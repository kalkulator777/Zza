# Правила работы в этом репозитории

Полная версия и обоснования — `AGENT_RULES.md`. Здесь короткая, обязательная.

## Для исполнителей (агентов)

1. **`DESIGN.md` — контракт. Ты его НЕ правишь.** Нужны изменения — присылай
   список правок в отчёте, дирижёр внесёт сам.
2. **Читай только те куски контракта, которые названы в задании.** Целиком не
   читать никогда: это сотни тысяч токенов впустую. Читай **по якорям**, а не
   по номерам строк — номера сдвигаются от любой правки контракта, якорь нет:
   `sed -n '/^## 5\./,/^## 6\./p' DESIGN.md`.
3. **Правь только файлы из своего списка.** Всё остальное — чужое.
   Нужен чужой файл — **доложи, а не правь**.
4. **Запрещены всем и всегда:** `git stash`, `git checkout <файл>`,
   `git restore`, `git add -A`, `git commit`, `git push`, любой force-push.
   Коммиты делает дирижёр.
5. **Приёмка числами.** Сказал «быстро» — приложи миллисекунды. Сказал
   «работает» — приложи, что именно запускал и что увидел.
6. **Новая проверка обязана уметь краснеть.** Сломай то, что она охраняет,
   покажи красный, верни обратно. Проверка, которая зеленеет на сломанном
   коде, хуже отсутствующей.
7. **Спорить можно и нужно.** Наткнулся на решение, которое меняет замысел
   задания, — доложи и объясни, не делай молча и не делай назло.
8. **Рядом с замером печатай `uptime`** (загрузку машины). Параллельный агент
   портит числа, и без загрузки их нельзя истолковать.
9. **Порог выводится из величины, а не подбирается под прогон.** Рядом с
   константой — вывод и запас.
10. **Не зацикливайся** «поправил — прогнал — ещё чуть-чуть». Прогнал один
    раз, доложил число.
11. **Отчёт в конце — короткий:** что сделано, чем проверено (числа), что не
    сделано и почему, что предлагаешь поправить в контракте.

## Среда (не обсуждается)

Astra Linux 1.8, Python 3.11, установка пакетов недоступна — только то, что
лежит в папке игры. Интернета на целевых машинах нет. Браузеры Firefox 143 /
Chromium 140. Локальная сеть работает.

## Про замеры графики

**В этом контейнере fps не меряется.** Здесь софтверный рендер (SwiftShader),
а цель — встроенная видеокарта офисного ПК. Любое число fps отсюда — мусор.
Делай стенд и инструкцию для замера на целевой машине, числа не выдумывай.
