# Режимы игры — согласованный список

Документ фиксирует, что делаем и в каком порядке. Правила описаны так, чтобы по ним
можно было писать код без додумываний.

## Ограничения, из которых всё следует

- Локальная сеть, **интернета нет вообще**: никаких CDN, шрифтов извне, `pip install` в момент запуска.
- Astra Linux, Python 3.11, tornado, Firefox 143 — парк однородный, полифилы не нужны.
- Игроков **2–6** (запас до ~10). Мышь, без тачскринов.
- Постоянного хранилища нет: всё в памяти процесса. БД не заводим.
  Сохраняется только то, что нужно для переподключения.
- Запуск — один `.py`, без деления на «сервер» и «клиент» в голове пользователя.

## Модель запуска и поиска лобби

Каждая машина запускает **один и тот же** `main.py`:

1. Поднимается tornado на первом свободном порту из диапазона (по умолчанию 8770+).
2. Автоматически открывается Firefox на `http://127.0.0.1:<порт>/`.
3. Экран выбора: **Создать лобби** / **Найти лобби**.
4. «Создать» — этот процесс становится хостом, комната живёт в его памяти.
5. «Найти» — локальный процесс шлёт UDP-broadcast по сети, собирает ответы хостов
   и показывает список: ник хоста, код комнаты, сколько игроков, какой режим.
   Клик → браузер переходит на `http://<ip-хоста>:<порт>/room/<код>?nick=...`.
6. Запасной путь, если broadcast зарублен файрволом: поле «подключиться по IP вручную».

Следствия, которые надо помнить:
- Ник передаётся в query, потому что после перехода на хост это уже другой origin —
  `localStorage` локального процесса туда не переедет.
- Токен игрока для переподключения кладётся в `localStorage` уже на origin хоста;
  обрыв связи или F5 не выкидывают из игры, место в раунде сохраняется.
- Уходит хост — умирает комната. Для LAN-посиделок это приемлемо, городить миграцию хоста не будем.

## Формат рисунка: векторные штрихи

Рисунок хранится не картинкой, а списком операций:

```json
[{"t":"pen","c":"#000","w":4,"p":[[10,20],[11,23]]}, {"t":"fill","x":50,"y":60,"c":"#f00"}]
```

Холст логически фиксирован (1000×750), на экране масштабируется по CSS.

Почему так: живая трансляция рисования в «Угадайке» — это сотни байт на пакет вместо
сотен килобайт PNG; плюс бесплатно получаются калька для анимации, undo, докачка
штрихов по ходу хода (таймаут не съедает работу) и нарезка рисунка на части для
«Изысканного трупа» и «Недостающей части». Заливка воспроизводится детерминированно,
потому что у всех одинаковый Firefox и одинаковый размер холста.

Сервер рисунки **не рендерит** — он хранит JSON и рулит таймерами.

## Два независимых движка

**Движок 1 — «Угадайка».** Раунд с одним активным художником, живой трансляцией штрихов,
чатом догадок и очками. Работает от 2 игроков.

**Движок 2 — «Альбом».** Цепочка шагов: альбом переезжает от игрока к игроку, на каждом
шаге задача `WRITE` или `DRAW`, видно только предыдущий шаг. Режим = конфигурация
цепочки: какие типы шагов, что показывать, откуда берётся старт, как считается таймер.
Все альбомные режимы ниже — это конфиг одного движка, а не отдельный код.

Важно при 2–4 игроках: длина альбома настраивается отдельно от числа игроков
(несколько кругов), иначе альбом из трёх картинок не успевает стать смешным.

## Состояние

Этапы 1 и 2 сделаны: играются Угадайка, Обычно, Сэндвич, Плагиат.
Дальше — этап 3.

## Этап 1 — ядро

### Угадайка (классический Gartic)

База. Один игрок рисует загаданное слово, остальные пишут догадки в чат.

- Художник выбирает слово из 3 предложенных, таймер 60–90 с (настраивается).
- Штрихи уходят на сервер батчами каждые ~80 мс и рассылаются всем — остальные видят
  рисование в реальном времени.
- Догадки сравниваются по нормализованной форме (регистр, `ё`→`е`, лишние пробелы).
  Расстояние Левенштейна 1 → «близко!», видно только автору догадки.
- Точное попадание: догадка скрывается от остальных, чтобы не спойлерить; игрок переходит
  в режим наблюдателя и может писать в чат уже без ограничений.
- Очки: угадавшим — тем больше, чем раньше; художнику — пропорционально числу угадавших
  (чтобы не было выгодно рисовать нечитаемо или, наоборот, подписывать словами).
- Подсказки: на 1/3 и 2/3 таймера открывается по случайной букве.
- Раунд заканчивается досрочно, когда угадали все.
- Художником становится каждый по кругу; число кругов настраивается.
- Инструменты: карандаш (3–4 толщины), ластик, заливка, палитра, отмена, очистить.
- Банк слов — свой, русский, по категориям, живёт в репозитории (без интернета иначе никак).

## Этап 2 — движок альбомов

### Обычно
Каждый пишет свою фразу → альбом уходит соседу, тот рисует → следующий подписывает
рисунок словами → и так далее. В конце альбомы показываются по очереди, шаг за шагом.

### Сэндвич
Первый пишет текст → все последующие только рисуют, каждый видит лишь предыдущий рисунок →
последний описывает словами. На показе сравниваем первую фразу с последней.

### Плагиат
Первый рисует по фразе, каждый следующий копирует предыдущий рисунок, и время на ход
уменьшается с каждым шагом (например 60→45→35→25→18→12 с). Итог — наглядная деградация копии.

## Этап 3 — остальные весёлые

### Анимация
Альбом = последовательность кадров. Каждый рисует свой кадр, видя предыдущий
полупрозрачной калькой. В конце — зацикленное воспроизведение, fps настраивается.

### Дополнение
Шаг 1: нарисовать несколько бессмысленных линий, короткий таймер (15 с).
Шаг 2: превратить эти линии в осмысленный рисунок.
Шаг 3: подписать словами. Дальше — как «Обычно».

### Изысканный труп
Холст делится на горизонтальные полосы по числу шагов. Каждый рисует свою полосу и видит
только нижние ~40 px предыдущей, чтобы продолжить линии. В конце показывается склейка целиком.

### Сотрудничество
Один холст на всех: по очереди каждый добавляет свои штрихи, видя всё нарисованное ранее.
Отличие от «Изысканного трупа» — ничего не скрыто.

### Недостающая часть
Холст делится на сегменты. На своём ходу игрок видит только часть сегментов предыдущего
рисунка и дорисовывает остальное; на следующем шаге часть уже его работы скрывается.

## Модификаторы, а не режимы

Это флажки в настройках комнаты, применимые к альбомным режимам:

- **Секрет** — промежуточные шаги скрыты до финального показа.
- **Фон** — первый шаг альбома рисует общий статичный фон, остальные кадры идут поверх него
  (осмысленно только вместе с «Анимацией»).

## Что сознательно не делаем

- **Шедевр** — ход без ограничения по времени превращается в мёртвую паузу для всех остальных.
- **История** — только текст, ни одного рисунка; в компании быстро становится скучно.
- **Соло** — игра в одиночку. Оставляем себе как режим отладки, в меню не показываем.
- **Ледокол** — механика та же, что «Обычно», отличается только банком личных вопросов.
  При желании включается позже одной галочкой.
- **Счёт** — субъективное оценивание «сохранился ли смысл», спорная и муторная механика.
